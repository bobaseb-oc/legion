# Tracks page — implementation plan (RED ZONE DRAFT)

Spec: `docs/superpowers/specs/2026-11-20-tracks-design.md` (with its steel-man addendum).
Jira: PLP · Branch: `feat/tracks` from `main` · One PR, commits ordered L1 → L2 → L3.

**Goal.** Replace the Explain page with a Tracks page: one card per live top agent under Legion,
the observer's read-only summary on top, the track's checklist below. The user pins, edits, moves
and drops checklist items; the agent cannot undo the user's items; no observer text reaches an agent.

**Architecture.** Pure track logic in `Explain.ts` (snapshot, card mapping, pin edits, stall
detection), unit-tested in `Explain.test.ts`. Server glue in `Server.ts` `export namespace Chat`
(`Chat.track` RED ZONE, `Chat.pinned`, `Chat.notes`, `Chat.stalls`, `state.tracks`). The agent side
in `Tools.ts` (`todo` gains `pinned`, strips server fields, reads/writes pins only through hooks).
Pins persist in `Memory.ts` (`mem.tracks`). Views: `View.ts`, `Cockpit.ts`, `Deck.ts`, `Term.ts`,
`web/src/Pages.ts`, `web/src/main.ts`; `web/app.js` rebuilt with `bun run web` and committed.

**Tech stack.** Bun + TypeScript. Tests: `bun run test [file]` only (wraps `test/run.sh`).

## Global Constraints (copied from the spec)

| Constant | Value | Meaning |
|---|---|---|
| `PINS` | 10 | pins per track |
| `PIN_TEXT` | 500 | characters per pin |
| `STALL` | 20 min | `doing` with no status change before a reminder |
| `REMINDS` | 3 / hour / agent | reminder cap |
| `EDITS` | 30 / min / chat | user edit rate cap |
| `NOTE_GAP` | 10 s | edit notes to one agent batched |

- A track = a live top agent (`parent === "main"`, not hidden, in `tools.agents`). Editable only if
  `role.$ === "sub"`; `cli` and `hands` tracks are read-only. Legion has no track (no `todo` tool,
  Tools.ts:624-626). Track identity comes from the crew tree, never from the observer.
- One writer per list: the agent writes `agent.todo` (Tools.todo); the server writes
  `mem.tracks` only on a view act (`Chat.track`) or the status-only `pinned` hook (`Chat.pinned`).
- Observer output reaches `chat.mem.explain` and views only. No path to `hooks.push`, `Tools.tell`
  or `Tools.remind`.
- Page key `tracks`. Terminal keeps `/explain` as an alias for one version. Web hash `#explain`
  routes to `#tracks` for one version. The `todo` page is unchanged.
- Reminder text is the fixed template only:
  `[Tracks] Item #<n> has been doing for 20 min with no change: mark it done, or say what blocks it.`
- Edit notes are fixed templates of the form `[Tracks] The user added pinned item #<n>: «<user text>».`
- Tests: never bare `bun test`. Tests bind local ports: run outside the sandbox if EPERM. Baseline:
  2 known failures in `local/prime/logs.test.ts` (mtime precision), not caused by this work.
- RED ZONE (user authority over agents, view-only act gating): every `Chat.track`, `Chat.pinned`,
  `Chat.stalls` and `Tools.todo` change is a draft. The human reviews and merges. Commit messages
  of those layers say `RED ZONE DRAFT`.
- Iteration caps (policies/iteration-caps.md): at most 3 run → analyze → edit cycles per failing
  test. On the 3rd failure stop and return `cap_hit`, `test_bug` or `ac_ambiguity`. Test-authoring
  typos do not count.

## Acceptance Criteria (PLP Task)

1. A `track` act from a device socket without the user's say is refused, and `mem.tracks` is unchanged.
2. An agent's whole-list `todo` call that omits pins leaves every pin's text, order and number.
3. `todo` `pinned` changes a pin's status by existing `n` only; text, order and unknown `n` are ignored.
4. `todo` input fields `by`, `since` and `reminded` are not stored.
5. No code in `Tools.ts` reads or writes `mem.tracks`.
6. Pin caps hold: 10 per track, 500 characters each, 30 user edits per minute per chat.
7. A pin number is never reused within a track.
8. Pins survive `Memory.load`; a corrupt `tracks` value loads as empty.
9. Edits on cli, hands and orphaned tracks are refused, except dropping an orphaned pin.
10. Dismissing a top agent removes its pins.
11. Each accepted edit reaches the owning agent as one fixed-template note per 10 s batch.
12. An idle agent gets no turn from a note; the note is read on its next turn; the view shows "queued, agent idle" until then.
13. A stall reminder holds only the template and a number, fires once per stall, at most 3 per agent per hour.
14. A stall reminder goes only to an agent with a live call, and its tokens are billed to the budget.
15. A snapshot with injected instructions changes no agent log and makes no `hooks.push` call.
16. The snapshot carries per-track item counts, never item text.
17. The page shows one card per track; observer cards for unknown names are dropped.
18. Web and terminal show and edit tracks, with all text escaped or cleaned; `/explain` and `#explain` still open the page.
